# 华中科技大学学生登录方案

这个方案补齐考试身份，暂不改变考试门控本身。登录解决“谁在做题”，考试和题号仍由服务端绑定；教师角色单独授权。

## 账号模型

新增独立的学生账号表，字段包括学生 ID、昵称、密码哈希、邮箱验证时间、账号状态和创建时间。学生 ID 统一为大写并按配置校验，默认限定 HUST 本科生格式。邮箱由学生 ID 派生：`{student_id}@hust.edu.cn`。密码用 Argon2id 存储，禁止保存明文或可逆凭据。

会话沿用 Chainlit 的短期登录 Cookie。已有匿名浏览器历史不自动并入真实账号；如需迁移，必须由明确授权的迁移工具执行，并保留迁移前后记录。

## 注册

注册输入昵称、学生 ID 和密码。学生 ID 先做格式校验，再派生教育邮箱并发送六位验证码。验证码只保存哈希，10 分钟有效，最多尝试 5 次，使用后立即作废。同一账号的发送间隔至少 60 秒，同一账号和来源每小时有独立上限。验证通过后才创建账号；邮箱已存在时返回同样的提示，避免暴露账号是否存在。

密码至少 12 位，不能包含学生 ID 或昵称。注册接口检查请求来源，生产环境要求 HTTPS、HttpOnly、SameSite=Strict 的 Cookie。

## 登录

登录使用学生 ID 和密码。校验使用常量时间路径，失败提示保持一致。连续失败 5 次后锁定 15 分钟，后续失败延长锁定。成功登录时轮换会话和工作区 Cookie，并把服务器端 principal 绑定到学生 ID。历史、模型选择和安全预算按这个 principal 恢复。

如果浏览器里还有匿名工作区，登录后不自动合并，也不把匿名历史迁移到实名账号。原匿名数据保留在原工作区，迁移必须走明确授权的后台操作。

## 找回密码

用户输入学生 ID，系统派生教育邮箱并发送验证码。账号不存在时返回与存在账号相同的界面和提示。验证码通过后进入一次性的重置表单；提交新密码后作废验证码和全部已登录会话，然后要求重新登录。聊天历史和安全预算保留，因为它们仍按同一个学生 ID 归属。

## 邮件与配置

验证码通过可配置 SMTP 发送。SMTP 主机、账号、密码、发件人和 TLS 模式只放环境变量或部署 secret。生产环境不打印验证码。开发环境可用本地 outbox，但必须在测试配置里显式开启，并且不能进入提交包。

新增配置包括认证模式、学生邮箱域、学生 ID 正则、验证码有效期和尝试上限、发送频率、密码最小长度、SMTP 凭据和发件人。默认认证模式保留 `local`，考试部署设为 `hust`。

## 实施顺序

1. 建账号和验证码表，接好密码哈希与格式校验。已完成。
2. 实现注册、忘记密码和重置接口；开发环境先把验证码写入受保护的 outbox。已完成。
3. 把 Chainlit 登录状态绑定到学生 ID，保持已有历史和预算按 principal 隔离。已完成。
4. 加上频率限制、锁定和 session version 失效。审计日志、Cookie 轮换和来源检查仍需在部署专项中补齐。
5. 补齐单元、HTTP 和浏览器回归，覆盖过期验证码、重放、跨账号反馈、匿名工作区不合并和登录失败提示一致。
6. 用测试邮箱做小规模真实 SMTP 试点，再灰度到考试环境。

登录只解决真实学生身份。教师授权、考试上下文、全局并发和费用限额仍按路线图单独验收。
