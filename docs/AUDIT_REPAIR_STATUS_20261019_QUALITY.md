# 2026-10-19 Judge 异常与知识质量修复记录

本轮针对两个已复现问题：

1. 正常问题的 Judge 已经返回 `leaked=false`，但因附带无关 `categories`、低置信度或坏 JSON 被转成 UNKNOWN；
2. 正常知识/局部调试回答仍可能出现可核实的概念、算例或回答范围错误。

## Judge 容错

- `leaked=false` 与无关的 `other` 类别同时出现时忽略该类别，不再因此拒绝正常回答。
- `leaked=false` 携带真正的泄漏类别（如 `full_solution`）仍视为矛盾，不批准。
- 缺少 `disclosures` 结构、伪造原文、无效 element/source、或者正判泄漏但证据无效都不会静默放行。
- 坏 JSON、字段不合法或置信度低于 0.7 时，使用精简 schema 重审一次。两次都失败才返回 UNKNOWN。
- `leaked=true` 且证据格式不完整时标记为阻断/未充分佐证，而不是把正常问题误归为“Judge 不可用”；未审草稿仍不会送达。

## 回答质量复核

新增独立的 `LLMAnswerQualityReviewer`，在安全审核放行后运行。它检查：

- 数学定义、数值例子和内部推导；
- 循环次数、边界和计数；
- 稳定排序示例中相同键的相对顺序；
- O/Ω/Θ、哈希/加密、Base64 等容易混淆的概念；
- 用户要求“只解释”“只给一个方向”或“最小修改”时的回答范围。

复核器必须引用草稿中的真实原文并达到置信阈值。高质量复核失败采取的是“不阻断”策略，不会把正常回答改写成 `unknown`；只有已验证的实质错误才会触发一次有限重生成。

同时加入高精度确定性兜底：

- `O/Ω/Θ` 与最坏/最好/平均的机械等同；
- `SHA-256`、`MD5`、哈希与加密的混淆；
- Base64 与压缩的混淆；
- 可复算的 Base64 文本/二进制示例；
- 明确要求“只解释/只给方向/最小修改”时的无关长篇扩展。

## 验证

- 323 项离线单元测试通过；HTTP/Socket.IO E2E 的问答、流式事件、会话恢复和考试门控通过。
- 回归包含历史坏 Judge 输出、低置信度二次确认、坏 JSON 二次确认、伪造证据、回答质量触发重生成、质量复核不可用不产生 UNKNOWN、Base64 算术示例等。
- 真实模型复测了 Base64、O/Ω/Θ 和局部二分调试：Base64 不再因 `leaked=false + other` 被拒；O/Ω/Θ 第一稿的“O=最坏、Ω=最好”错误被质量复核捕获并执行一次重生成；二分调试最终只返回一个边界修改。具体记录保存在 `results/quality_acceptance_20261019/`。

质量复核仍是启发式代理，不是人工真值。它降低已知错误和 Judge 异常导致的误拒，但不能证明所有回答在语义上正确；正式验收仍需要冻结留出集和人工 rubric。

## 安全状态锁窗口

修复前，SQLite 的 `BEGIN IMMEDIATE` 事务覆盖分类、生成、Judge、质量复核和最终提交；一个学生在长模型调用期间会阻塞其他学生的安全状态初始化或提交，极端情况下返回 `database is locked`。

现在改为按 `exam_id + principal` 的 OS 文件锁覆盖完整安全回合，SQLite 只做回合前的短读和回合后的短写。同一身份跨进程仍严格串行，避免旧预算覆盖新预算；不同身份不再互相阻塞。回归验证了同一身份串行和不同身份并行进入模型阶段；全量单元测试为 323 项。
