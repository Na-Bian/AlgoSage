# ExamGuard 正式版路线图

目标：将 ExamGuard 推进为可维护、可验收的正式产品。正式发布以版本对应的行为、安全和运行验收为依据。

## 已有基础

已有输入分类、可信帮助等级、受限生成、安全审核、知识复核、多轮披露预算、模型选择、附件输入、自动标题和本地历史恢复。2026-10-20 的离线基线为 351 项单元测试通过。历史真实模型批次属于开发回归，不作为当前版本的留出集验收。

## 推进顺序

1. 多模态审核闭环：分类、生成、泄漏审核和知识复核使用相同的有界图片上下文；图片内的请求和指令不能绕过输入判断；历史图片追问也进入复核。
2. 回答可靠性：补齐短回答和复核不可用的可观测边界，建立经过核对的课程知识与算例，降低事实错误和误拒。
3. 历史与反馈：持久化前端附件元素和可下载原件，完善删除与访问隔离；反馈与纠错真正落库。
4. 考试身份：绑定真实学生、考试和题目，验证跨会话预算与教师权限。
5. 运行能力：并发压测、全局调用与费用限额、任务取消、故障恢复、备份恢复演练和部署文档。
6. 发布验收：冻结新留出集、重复真实模型评测、负责人复核、记录误拒/泄漏/正确性/UNKNOWN 的分母；干净环境安装与版本对应的源码、配置、报告和证据。

## 发布门槛

- 所有已知严重安全和数据隔离缺陷关闭，并有可复现的回归。
- 当前版本完成正常问答、局部调试、合法提示、单轮及多轮攻击、图片和文档的真实行为验收；阈值在冻结评测前确定。
- 人工复核与系统自审核分开统计，保留失败、待复核及不可判定结果。
- 部署规模、延迟目标、费用和恢复能力有实际测试依据；未经验证的场景写明边界。
- 发布标记对应固定提交及配置；历史开发结果不得作为新版本的通过证明。

本仓库上传只建立可追踪的开发基线，不表示正式版验收已经完成。私有密钥、用户聊天、运行库和原始开发审核日志保留在本地。
