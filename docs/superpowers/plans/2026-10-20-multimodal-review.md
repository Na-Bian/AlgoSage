# 多模态审核上下文修复计划

目标：分类、生成、安全 Judge 和知识复核看到同一组有界图片，修复仅生成器看图的上下文缺口；仍以正式版为后续发布目标。

设计：共享图片上下文模块，当前附件优先，再选最近用户历史图片，总计最多六张、按数据 URL 去重。历史图片只有被本轮选中才进入生成请求，缺失的图片有明确文字提示；图片文件名、来源说明和像素均为不可信数据。图片分类不可用时沿用 uncertain 保守等级，安全 Judge 看图失败仍为 UNKNOWN，不提供未审草稿。

- [ ] 先写失败回归：图片内越狱、合法读图、历史图片追问、超过六张的优先级，以及安全/知识复核收到原图。
- [ ] 实现共享图片选择与消息内容构造，接通 hybrid、生成器和两种复核，保持纯文本调用兼容。
- [ ] 验证 Judge 修复请求保留图片、并行与顺序审核等价、原文证据和预算没有弱化。
- [ ] 全量单元及 HTTP/Socket.IO E2E；隔离真实模型实例通过浏览器做合成图片正反例，保存记录。
- [ ] 更新接口文档与修复状态，提交并推送修复分支供审查。

边界：不同时重构身份、附件元素存储或全部质量策略；后续按正式版路线图逐项推进。图片识别和同模型审核仍可能出错，本轮不能替代完整正式版验收。
